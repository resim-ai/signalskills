## Data profile
Read from all four parquet files (2026-09-28).

| Field | Range | Cadence / shape | Notes |
|---|---|---|---|
| `t_ns` | 0 → 59.9 s, every drive | 10 Hz, dt exactly 100 ms, no gaps | Starts at 0 in every drive: time since drive start, not wall clock. |
| `speed_mps` | −0.20 → 2.07 | varies | Negative about half the time while IDLE (noise around 0). |
| `cmd_speed_mps` | 0 → 1.98 | varies | Exactly 0 for 95 / 75 / 22 / 23 % of drives 01–04. Drives 01–02 barely move (max cmd 0.14 / 0.29). |
| speed − cmd | abs mean 0.040–0.042, RMS 0.050–0.052, p90 0.079–0.087, max 0.16–0.20 m/s | varies | Same size in AUTO and IDLE and in every drive, fast or parked: looks like added noise, not a controller. |
| `battery_pct` | 95.0 → 80.0, every drive | **exactly linear**, −0.02504 % per sample | Synthetic. Drain rate is 15.03 %/min in all four drives and does not change with speed or mode. |
| `mode` | `AUTO` / `IDLE` only | changes 6 / 34 / 12 / 15 times (drives 01–04) | Time in AUTO: 0.7 / 6.5 / 41.8 / 43.6 s. Drive 02 has 14 single-sample (100 ms) mode flips. **No obstacle-avoidance value.** |
| `motor_temp_c` (drive_04 only) | 40.0 → 55.0 | exactly linear | Synthetic: `motor_temp_c + battery_pct` = 135 on every row. |

What the user asked for, against the data:
- **Speed tracking error over time:** supported (`speed_mps − cmd_speed_mps`).
- **Battery drain rate:** computable, but a flat 15.03 %/min in every drive, because the battery signal is synthetic. Charted anyway so real drives show up once they arrive.
- **Time in obstacle-avoidance mode:** **not supported.** `mode` has only `AUTO` and `IDLE`, and no other column marks obstacles or avoidance. Needs one of: a `mode` value such as `AVOID`, a boolean avoidance-active column, or a planner/obstacle-distance field to derive it from.
