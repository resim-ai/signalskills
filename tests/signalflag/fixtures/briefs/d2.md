## Current state
- `eval_checkpoint.py <ckpt>` evaluates one checkpoint over 5 seeds (0–4). Writes `evals/<YYYYmmddTHHMMSS>/episodes.csv` (seed, return, success, episode_len) and `log.txt` (`loaded <ckpt>`).
- Checkpoint step is only recoverable from `log.txt`; commit and dirty-tree state are not recorded.
- `tests/test_eval.py`: one pytest check, 5 seeds returned.
- Run while training continues, once per new checkpoint. On disk: 4 runs, ~5 rows each.

## Intent
Rank checkpoints by mean return and success rate, and see whether they're still improving as training goes. Asked by the researcher; exploration, not a gate. Metrics-first.

## Control

## Data profile
Read from all 4 `episodes.csv` (5 rows each, seeds 0–4 in every run) and `eval_checkpoint.py`.

| Field | Range seen | Varies? | Notes |
|---|---|---|---|
| `seed` | 0–4 | same set every run | Stable test names; one seed can be followed across checkpoints. |
| `return` | 53.6–95.2; batch means 59.9 → 71.4 → 80.3 → 92.7 | yes, rises with step | Code: `50 + step/1000 + N(0, 5)`. Synthetic, linear in step. Within-batch sd 2.9–5.0. |
| `success` | 0.0 → 0.6 → 1.0 → 1.0 | saturates | Not observed: code sets `success = return > 70`. Redundant with return; at 1.0 from the 3rd run on, so it stops ranking checkpoints. Margin `return − 70` keeps ranking. |
| `episode_len` | 210–385 | yes, no trend | Code: `integers(200, 400)`, independent of step and return (corr −0.26 to 0.59 on n=5). Noise as written. |
| `log.txt` | `loaded checkpoints/ckpt_<step>` | one line | Only step source. No timing, errors or per-episode data. |

- One test = one row of 3 numbers. No time series, no mode/state field, no camera or replay.
- n = 5 per checkpoint: success rate moves in 20% steps; sd is a rough estimate.
- `20260901T020000`: `evaluate("ckpt_30000")` reproduces its returns exactly (the rng is seeded by step). Holds only if the eval code hasn't changed since that run; user to confirm before backfill.
